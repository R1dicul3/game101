# 透视投影的三段式:S · T · persp

> 小知识点记录 —— 来自 HW1 `get_projection_matrix` 的实践。

## 一句话

投影矩阵不是直接"猜"出来的,而是**三个矩阵相乘**:

```
P = S · T · persp
```

- `persp` —— 透视压缩:把视锥压成一个长方体(近大远小在这一步发生)
- `T` —— 平移:把这个长方体搬到以原点为中心
- `S` —— 缩放:把长方体缩成 `[-1,1]^3` 的标准立方体(NDC)

代码里就是一行:

```cpp
projection = S * T * persp;
```

## 顺序为什么是 S · T · persp

矩阵**从右往左**依次作用在坐标上:

```
v_clip = S · (T · (persp · v))
         ↑     ↑        ↑
        最后  中间     最先作用在顶点上
```

所以写乘法时"最后做的"写在最左边。搞反成 `persp * T * S` 画面会完全乱掉。

## 三个矩阵分别长什么样

### persp —— 透视压缩

```
           | n  0   0    0  |
persp  =   | 0  n   0    0  |
           | 0  0  n+f  -nf |
           | 0  0  -1    0  |
```

**最后一行 `[0, 0, -1, 0]` 是整个透视的灵魂**:它让 `w = -z`,
后面除以 `w` 时,越远的点 `w` 越大、坐标越小 —— 这就是"近大远小"。

写成 `[0,0,0,1]` 就退化成正交投影,画面会变成平面图。

### T —— 平移(把盒子中心搬到原点)

```
        | 1  0  0  -(r+l)/2 |
T   =   | 0  1  0  -(t+b)/2 |
        | 0  0  1    *      |
        | 0  0  0     1     |
```

前两行的平移量很直观:盒子左右范围是 `[l, r]`,中心在 `(r+l)/2`,所以平移 `-(r+l)/2` 就能把中心对到 0。

**z 那一项的平移量比手写的多出一个系数**(见下面的"陷阱"),因为 `persp` 的 z 行不是标准的 `n+f, -nf` 形式,它把 z 压缩到了一个非标准区间。

### S —— 缩放(把盒子缩成 [-1,1]³)

```
        | 2/(r-l)     0          0         0 |
S   =   |   0      2/(t-b)       0         0 |
        |   0         0       2/(f-n)      0 |
        |   0         0          0         1 |
```

宽度 `r-l` 要变成 2,所以缩放因子是 `2/(r-l)`;高和深同理。

## l, r, b, t 四个值怎么来

这四个是**近平面的左右下上边界**,由 `eye_fov`、`aspect_ratio`、`zNear` 反推:

```cpp
const float fov = eye_fov / 180.0f * float(M_PI);   // 度 -> 弧度
const float t = n * tan(fov / 2);    // 上边界:半视角 × 近平面距离
const float b = -t;                  // 下边界(对称)
const float r = t * aspect_ratio;    // 右边界:横纵比拉伸
const float l = -r;                  // 左边界(对称)
```

要点:

1. `eye_fov` 是**垂直**方向整角,所以用 `tan(fov / 2)`"半角";
2. 一定要先转弧度 —— `tan(22.5)` 是把 22.5 弧度(约 1289°)拿去算,结果是错的;
3. `t` 要乘 `zNear`:近平面越远,同样的视角张开的范围越大;
4. `aspect_ratio = width / height`,横向按它拉伸,所以 `r = aspect · t`。

### 代入 fov=45°, aspect=1, zNear=0.1

```
fov/2 = 22.5°  ->  tan = 0.414214
t = 0.414214 × 0.1 = 0.0414214
b = -0.0414214
r = 0.0414214   (aspect = 1)
l = -0.0414214

r - l = 0.0828428  ->  2/(r-l) = 24.155
2n/(r-l) = 0.2 / 0.0828428 = 2.41421   ← 就是投影矩阵的 (0,0) 项
```

## 数值自检

矩阵算完一定要验三个深度,三个都对了才算对:

| 检验点 | `z_ndc` 应该是 |
|---|---|
| 近平面 `z = -zNear` | **-1** |
| 远平面 `z = -zFar` | **+1** |
| 场景里的顶点(如 `z=-7`) | 落在开区间 `(-1, 1)` 内,此处 0.9754 |

```cpp
// 用 P 直接乘齐次坐标,再除以 w
Eigen::Vector4f clip = P * Eigen::Vector4f(2, 0, -7, 1);
std::cout << (clip / clip.w()).transpose();
```

## 陷阱:两段式合成的 z 行常数

按"persp × T × S"手抄时,`T` 和 `S` 里 **z 方向的两个常数**最容易搞反:

| | 容易写错 | 正确(配合上面的 persp) |
|---|---|---|
| `S` 的 z 缩放 | `2/(n - f)` | `2/(f - n)` |
| `T` 的 z 平移 | `-(n + f) / 2` | `3 * (n + f) / 2` |

错的时候有个非常迷惑的特征:

> **x、y 全对,画面看起来完全正常**,只有 `z_ndc` 是坏的(实测会跑到 3.0 附近,远超 `[-1,1]`)。
> HW1 不做深度测试,所以肉眼看不出来;到 **HW2 的 Z-Buffer** 才会突然全线崩塌。

## 等价写法:直接填 8 个元素

把三段乘开,就是下面这个矩阵(推荐直接用,每一项都能独立验证):

```
       | 2n/(r-l)     0        (r+l)/(r-l)        0       |
P   =  |    0      2n/(t-b)     (t+b)/(t-b)        0       |
       |    0         0        -(f+n)/(f-n)   -2fn/(f-n)   |
       |    0         0             -1             0       |
```

```cpp
Eigen::Matrix4f P = Eigen::Matrix4f::Zero();
P(0, 0) = 2 * n / (r - l);      P(0, 2) = (r + l) / (r - l);
P(1, 1) = 2 * n / (t - b);      P(1, 2) = (t + b) / (t - b);
P(2, 2) = -(f + n) / (f - n);   P(2, 3) = -2 * f * n / (f - n);
P(3, 2) = -1.0f;
```

两种写法**逐元素完全相同**(已数值验证),但单矩阵版少两个容易记错的常数。
