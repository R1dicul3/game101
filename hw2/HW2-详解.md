# HW2 详解 —— 光栅化与 Z-Buffer

> 目标:把 HW1 投影到屏幕上的三角形**真正填成像素**,并用深度缓冲正确处理遮挡。
> 你要实现的只有 `rasterizer.cpp` 里中部标注的两个函数。

---

## 一、数据流

```
Triangle(世界坐标)
   │  mvp = projection * view * model
   ▼
clip = mvp * v          ← 齐次坐标
   │  除以 w(透视除法)
   ▼
ndc = clip / w          ← [-1,1]^3
   │  视口变换
   ▼
(屏幕 x, 屏幕 y, NDC z)  ← 传给 rasterize_triangle
   │  ★ 你的代码
   ▼
frame_buf_(颜色) + depth_buf_(深度)
   │  resolve() 降采样
   ▼
700x700 PNG
```

框架已经做到"视口变换"为止,**剩下的全部是你的**。

## 二、坐标系约定(最容易搞混的地方)

| 量 | 范围 | 说明 |
|---|---|---|
| 屏幕 x | `[0, width)` | 向右为正,**0 是最左边** |
| 屏幕 y | `[0, height)` | **向下**为正(图像坐标),NDC 的 +y 在上面,所以视口变换里已经翻转过 |
| NDC z | `[-1, 1]` | **-1 是近平面,+1 是远平面**,所以 **z 越小越近** |

记住最后一条:Z-Buffer 里"更近"意味着 **z 更小**。

## 三、函数 ①:insideTriangle

判断点是否落在三角形内。用**有向面积(二维叉积)**:

```cpp
// 对三条边分别算叉积:d0, d1, d2
float d0 = cross(b - a, p - a);
float d1 = cross(c - b, p - b);
float d2 = cross(a - c, p - c);
```

- 三个值**同号**(都 ≥0 或都 ≤0)→ 点在内部
- 一正一负 → 在外部

**为什么不能直接判断"都 ≥ 0"**:三角形的顶点在屏幕空间可能是顺时针,也可能是逆时针(取决于朝向和屏幕翻转),叉积的符号会整体反号。所以要么统一处理,要么用下面这个更稳的写法:

```cpp
bool any_neg = (d0 < 0) || (d1 < 0) || (d2 < 0);
bool any_pos = (d0 > 0) || (d1 > 0) || (d2 > 0);
return !(any_neg && any_pos);      // 三个同号即在内部
```

> 退化情形:三角形在屏幕上退化成一条线时面积为 0,此时永远返回 true,
> 会在 `rasterize_triangle` 里通过 `|area| < eps` 提前 return 掉。

## 四、函数 ②:rasterize_triangle

### 4.1 包围盒

只在三角形的外接矩形里遍历,**别遍历整屏**(700×700 每帧二次方):

```cpp
int minx = floor(min({a.x(), b.x(), c.x()}));
int maxx = ceil (max({a.x(), b.x(), c.x()}));
int miny = floor(min({a.y(), b.y(), c.y()}));
int maxy = ceil (max({a.y(), b.y(), c.y()}));

// 必须 clamp!超采样模式下三角形可能有一部分出界
minx = std::max(minx, 0);          maxx = std::min(maxx, buf_width()  - 1);
miny = std::max(miny, 0);          maxy = std::min(maxy, buf_height() - 1);
```

### 4.2 像素中心

取像素**中心**,不是左上角:

```cpp
const float px = x + 0.5f;
const float py = y + 0.5f;
```

用 `x, y` 直接判断会整体偏移半个像素,边缘会出现规律性的锯齿错位。

### 4.3 重心坐标

三顶点 `a, b, c` 对应权重 `wa, wb, wc`,满足 `wa + wb + wc = 1`。
用叉积(或行列式)求,三种"面积比"写法等价:

```cpp
const float area = (b.x()-a.x())*(c.y()-a.y()) - (b.y()-a.y())*(c.x()-a.x());
const float wa = ((b.x()-px)*(c.y()-py) - (b.y()-py)*(c.x()-px)) / area;
const float wb = ((c.x()-px)*(a.y()-py) - (c.y()-py)*(a.x()-px)) / area;
const float wc = 1.0f - wa - wb;          // 比直接算省一次除法
```

重心坐标的三个分量天然满足"都在内部时非负",所以 `insideTriangle` 其实可以省掉,
直接判断 `wa >= 0 && wb >= 0 && wc >= 0` —— 两者本质是一回事,看你喜欢哪种。

### 4.4 深度插值

```cpp
const float z = wa * a.z() + wb * b.z() + wc * c.z();
```

**为什么在屏幕空间线性插值 NDC z 是对的?**
因为 NDC 里的 z 已经是 `z_clip / w`,透视除法做过了;
它在屏幕空间里对三角形是仿射的,所以线性插值精确。
(反而是**不**能线性插值的是视图空间的 z 和纹理坐标 —— 那要用 `1/w` 做修正,这是后面的内容。)

### 4.5 Z-Buffer

```cpp
if (z >= r.get_depth(x, y)) continue;    // 不是更近,丢弃
r.set_depth(x, y, z);
r.set_pixel({float(x), float(y), 0.f}, color);
```

| 项 | 值 |
|---|---|
| 初始化 | `+infinity`(比任何真实深度都远) |
| 比较 | **严格更小**才通过 |
| 原因 | NDC z 越小越近,近的应该覆盖远的 |

若写成 `z > depth`,遮挡会完全反过来 —— 远的盖住近的。

## 五、提高部分:2x2 超采样(SSAA)

框架已经内置,你不用改代码 —— 只是**你的光栅化必须以 `x + 0.5f` 为采样中心**,
这样在放大 2 倍的缓冲里,一个原像素自然被 2×2 个样本覆盖。

```bash
bash run.sh 2        # 2x2 超采样
bash run.sh both     # 1x 和 2x 都出,直接对比边缘
```

工作原理:内部缓冲放大 `sample_scale` 倍光栅化 → `resolve()` 把 s×s 个样本颜色取平均。
三角形边缘的像素会得到"半红半黑"的平均色,于是锯齿消失。


- 着色像素为 0 → 还没实现
- 深度范围应该是两个值(红 0.9754 / 蓝 0.9886),若只有一个值说明某个三角形没画上

**② 参考实现对照**

**③ 肉眼判据**

红三角在前、蓝三角在后,蓝只在红的下方露出来一条边。
如果蓝把红盖住了 → z 比较方向写反了。

## 七、错误 → 症状对照表

| 症状 | 病因 |
|---|---|
| 全黑 | 两个函数还空着 |
| 只有三角形轮廓/只有一条边 | `insideTriangle` 符号判断只写了"三个都 ≥0" |
| 三角形整体偏移半个像素、边缘抖动 | 没取像素中心 `(x+0.5, y+0.5)` |
| **蓝色盖住红色**(应该反过来) | z 比较方向写反 |
| 全屏同色 / 颜色溢出到包围盒外 | 忘了 clamp 包围盒,或 `set_pixel` 越界写 |
| 颜色闪烁、边缘黑边 | 深度和颜色写到了不同坐标(比如 `(x, y)` 和 `(x+0.5, y+0.5)` 混用) |
| 2x 模式下画面缩小一半 | 视口变换用了 `width` 而不是 `buf_width()`(框架已处理,别自己再算) |
| 程序极慢 | 遍历了整屏而不是包围盒 |
